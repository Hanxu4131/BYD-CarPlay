# 第30版：原车歌曲显示与媒体会话分开

BYD Carplay 第30版（2026-10-03）
版本0.2.9-tang21-test30，versionCode58，基于第29版。

歌曲与歌词
原车歌曲栏显示：只控制向原车中控／仪表歌曲栏写入，不控制嘟嘟读取。
原车歌曲栏显示歌手：只改变原车栏“歌词／歌曲名 — 歌手”的格式，默认开启。
媒体会话始终发布手机原始的歌词／歌曲名、歌手、播放状态；关闭任一原车开关不删改这些字段。
旧平台没有新版比亚迪导航软件包时，按原车仪表SDK方法是否存在显示歌曲开关。新版导航输出的适用机型检测保持原样。

原车写入
旧工具不写任何字段也用2.9～5.5秒，其中一次内部SDK阶段约128ms、输出前2728ms。说明进程调用外围等待是显著部分，不足以证明iPhone视频歌词延迟来源。
改成一次初始化原车接口，复用既有已授权ADB的独占stdin/stdout shell流，避免每句歌词启动app_process；不创建新的TCP服务，不改变Wi-Fi或原ADB地址、密钥和配对。
原车开关开启且CarPlay会话有效时预热；没有歌名时不调用setter。初始化后再核对会话代次，关开关/断开会使旧初始化失效。
输入验证随机128bit token；只允许device1007已有source11、state1/2/3、UTF16LE最多255字节文本。每个请求最多1024字节、响应4096字节/64帧，初始化等待和单次更新有总时限。
只更新最新内容；源和播放状态分项缓存。source失败不假记成功，每30秒重试；state失败每5秒重试。
原车开关关闭或断开时，已有写入发送stop清状态；预热尚未写入只close退出。每5秒续租，失联超过15秒退出。stop不可达时不能保证立即清原车卡片；过期进程不再清卡，避免擦掉新会话信息。

HEVC
H.264分屏自适应不会在HEVC下开启。新增直角遮罩声明仅用于H.264；HEVC回到第28版显示声明，切屏仍按原逻辑，不承诺HEVC不断连。
这是兼容性修正，HEVC本次连不上尚需正式重连日志确认；未改网络配置。

核验边界
歌曲/metadata/交互ADB共18项单元测试通过，另跑dispatcher测试与整包编译/lint。
临时run-as只读探针表面返回Killed；补查crash日志实际是LocalSocket.connect Permission denied。因此最终版删除辅助socket，改用原ADB授权流。临时文件和测试进程已清理。正式安装后以应用自身日志/实际原车显示验收。
原车SDK应答耗时和原车屏幕真正显示的时刻分开记录。仍需用户核对歌词是否贴近实时，不承诺已消除全部3秒延迟。
保留第29版显示调整。网络目录、orchestration、AirPlayPersistence、BydAdbShell逐字节保持第29版。LocalAdb新增独占交互shell API；原connect、普通shell、handshake、地址和端口常量逐字节不变。

正式安装后补充（17:43）：已确认应用自身持久ADB通道正常，原车连续text写入应答成功，queueMs0～4、writeMs16～40。用户回复“修好了”。屏幕显示主观验收以该回复为准，不将SDK应答耗时当作像素呈现耗时。设置中的显示歌手开关已随同安装。HEVC兼容修正已装，仍未取得开启HEVC后成功重连的实测证据。

用户后续反馈：仍有约0.5～1秒显示差距。当前已测的原车写入应答16～40ms不能解释全部差距；未确认是手机元数据时机还是原车显示刷新，不能宣称全链路无延迟。当前路径按iAP2当前title/artist更新，没有未来歌词时间轴，未加入负时间偏移或猜下一句。只读SDK方法检查未发现公开getMediaInfo方法；sourceOTHERS=11确认与车机常量一致。
